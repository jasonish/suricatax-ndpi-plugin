# ndpi-sys

Rust `-sys` crate that builds **nDPI 6.0** from the vendored source tree at
`vendor/nDPI`.

## What this crate does

- Compiles nDPI C sources with `cc`.
- Generates required nDPI config headers (`ndpi_config.h`, and `ndpi_define.h`
  from `src/include/ndpi_define.h.in`) in `OUT_DIR`.
- Exposes raw FFI bindings in `src/bindings.rs`.

## Build requirements

- A C toolchain (`cc`, `ar`) available in your environment.
- On Unix-like platforms, links against `libm`.

## Notes

- Optional nDPI integrations (PCRE2, MaxMindDB, nBPF, external libgcrypt, etc.)
  are not enabled in this build.
- Global context support (`USE_GLOBAL_CONTEXT`) is enabled, as with nDPI's
  default configure, so detection modules can share LRU caches. Runtime
  dissector plugins and USDT probes are not enabled.
- The upstream nDPI `tests/`, `fuzz/`, and `dga/` trees are not vendored, as
  this crate builds only the library sources. DGA runtime code/data used by the
  library remains under `src/lib`.

## Regenerating bindings

`src/bindings.rs` was generated with `bindgen` 0.73 against the headers
generated by `build.rs` (found in `target/*/build/ndpi-sys-*/out/include`):

```sh
INC=$(ls -td target/debug/build/ndpi-sys-*/out/include | head -1)
bindgen "$INC/ndpi_api.h" --rust-target 1.75 --no-layout-tests \
    --allowlist-function 'ndpi_.*' --allowlist-type 'ndpi_.*' \
    --allowlist-var 'NDPI_.*|ndpi_.*' --opaque-type ndpi_lru_cache \
    -- -I"$INC" -D_DEFAULT_SOURCE=1 -D_GNU_SOURCE=1 -DUSE_GLOBAL_CONTEXT \
    > ndpi-sys/src/bindings.rs
```

`ndpi_lru_cache` is kept opaque: with `USE_GLOBAL_CONTEXT` it embeds a
`pthread_mutex_t`, and its fields are not needed from Rust.

Older `bindgen` releases may emit an opaque `ndpi_flow_struct` with recent
versions of clang.
